# AINS 화면 스타일 적용

기준: CTDS 0.4.4, Spare / light / calm / hue 100 · chroma 0.05 / standard / default / calm / ko / Lucide.

`platform/web/src/styles.css`의 기존 화면 구조와 반응형 분기점을 유지하면서 색상·간격·서체·모서리·동작을 CTDS 토큰으로 교체했다. 오래된 `--ink`, `--line` 등의 별칭은 공식 의미 토큰을 참조한다. `--muted`는 CTDS 표면색과 이름이 충돌하므로 AINS 본문에서는 `--fg-muted`를 사용한다.

- 콘텐츠 글자 크기는 `--text-sm`, 보조 표기는 최소 `--text-2xs`를 기준으로 한다.
- 섹션·폼·리스트 간격은 `--space-*`, 모서리는 `--radius-*`, 포커스는 `--ring-*`, 동작은 `--transition-*`를 사용한다.
- 상태 의미는 `--success`, `--warning`, `--destructive`, `--info` 및 각 subtle/border 토큰에 매핑한다.
- 장식용 배경 원, 맥동, 페이지 진입 애니메이션을 제거했다. 정보 안내는 가능한 한 인라인 표기로 정리했다.
- 공통 Button/Badge/EmptyState/Tabs/Select/Input의 외형은 공식 CTDS 컴포넌트에 맡긴다. 기존 클래스는 레이아웃만 유지하고, 이전 외형 규칙은 `:not([data-ctds])`로 제한한다.
- 컨트롤 루트의 `data-ctds`와 내부 `data-ctds-control` 속성으로 기존 시각 규칙을 제외한다. 입력·선택·파일·체크박스는 실제 CTDS 컴포넌트로 연결한다. 상위 CSS는 구조 배치만 담당하며 선택 상태는 CTDS variant/선택 API로 표현한다.
- Radix 기반 CTDS Modal의 포커스·배경·애니메이션은 공식 컴포넌트가 관리한다. AINS는 `.ains-modal` 폭과 `.ains-modal-content` 스크롤만 구성한다.

## 간격의 책임

CTDS의 `--space-*`는 간격 **값**을 제공하지만, 페이지에 빠진 gap이나 padding 선언을 자동으로 채우지는 않는다. AINS는 다음 공통 조합을 필요한 화면에 명시적으로 적용한다. 전체 기존 화면이 이 조합으로 전환된 것은 아니다.

| 공간 | 담당 |
| --- | --- |
| 독립된 안내·보드·섹션 사이 | 부모 `.ains-section-stack`의 `gap: var(--space-4)` |
| 독립된 클릭 카드 안쪽 | AINS Button 확장 `layout="card"`의 `padding: var(--space-3)` |
| 안내 본문의 목록 | `.ains-prose-list`의 토큰 기반 들여쓰기·항목 간격과 기본 margin 정리 |
| 안내의 제목·본문·행동 사이 | CTDS Callout의 슬롯. `Notice` 버튼은 `actions`로 전달 |

부모 gap은 형제 박스 **사이**, 카드 padding은 박스 테두리와 내용 **사이**를 담당한다. 두 공간을 구분하고, 같은 경계에 부모 gap과 자식 margin을 중복 적용하지 않는다. 하나의 이어진 패널 안에서 헤더·본문이 접하는 경우에만 외부 gap을 생략할 수 있다. 전역 `section`·`article`·`ul` 선택자로 간격을 강제하지 않는다. 기존 `layout="content"`의 동작과 여백은 유지한다.

## 구조 크기 예외

`:root`에 정의된 `--ains-*` 토큰은 화면 구성 제약이다. 최소 뷰포트, 작업 공간 상한, 3단계 보조 패널, 폼 상한, 일반/넓은 대화상자 상한만 지정한다. 색상·폰트·컨트롤 모서리 값을 복제하는 용도로 사용하지 않는다. 미디어 쿼리의 분기점은 CSS 사용자 정의 속성을 사용할 수 없어 기존 리터럴 분기점을 유지한다. 실제 카드/폼 내부 간격은 Density 축에 반응한다.

## 확인

PostCSS 파싱 및 변수 참조 검사는 유령 토큰과 스타일 리터럴을 찾는다. 토큰이 존재하거나 CTDS 컴포넌트를 사용한다는 사실만으로 실제 화면의 간격이 맞는 것은 아니다. 간격을 변경할 때에는 해당 사용처를 브라우저에서도 확인한다.

반복 검사 명령: `npm run check:ctds`. AINS 소유 CSS/JSX의 하드코딩과 미정의 변수, 구조 치수 토큰의 비구조적 사용을 검사한다. CTDS 원본 구현의 리터럴은 수정 대상에서 제외하고, 정의된 변수 목록으로만 읽는다. 리터럴 색상·치수·폰트와 미정의 변수 샘플을 주입한 임시 검사에서 실패 종료 코드도 확인했다.

간격 변경의 브라우저 검증에는 실제로 데이터가 있는 화면을 사용한다. `compact`·`default`·`comfortable` 세 density와 좁은 뷰포트에서 다음을 확인한다.

- computed style의 부모 gap이 해당 density의 `--space-4` 값으로 해석되고, 안내와 다음 보드의 실제 경계 사이에도 그 간격이 남는지 확인한다.
- 카드 네 면의 computed padding이 `--space-3`으로 해석되고, 첫 배지·여러 줄 제목·마지막 메타데이터가 테두리에 붙거나 잘리지 않는지 확인한다.
- 목록과 행동 버튼이 의도한 슬롯에서 분리되고, 긴 문구가 좁은 화면에서 넘치지 않는지 확인한다. 의도된 칸반 가로 스크롤은 페이지 전체의 가로 넘침과 구분한다.
- 기존 `layout="content"` 컨트롤과 일반 버튼의 크기·정렬이 바뀌지 않았는지 함께 확인한다. 정적 검사 통과를 이 시각 검증의 대체 근거로 사용하지 않는다.
