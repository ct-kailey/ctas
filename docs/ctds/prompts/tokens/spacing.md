# Spacing

### 원칙
관계의 밀도를 시각화. 가까울수록 관련 강하고, 멀수록 문맥 분리.
4px 배수(`--space-*`)만 사용. Density 축이 `--space-scale`로 계열을 통째로 스왑.

### Do
공간은 **"맥락"으로 선택**한다. 토큰에 고정 용도가 박혀있지 않다. 아래 두 리듬 중 하나를 먼저 고르고, 그 안에서 스케일을 쓴다.

**앱·대시보드·콘솔 (디폴트 — 매일 쓰는 UI)**
- 작은 컴포넌트 사이(버튼↔버튼, 칩↔칩, 아이콘 묶음): **`space-1`(4px) 고정.** 묶음으로 읽히는 밀도. `space-2` 이상 금지.
- 컴포넌트 내부 요소(버튼의 아이콘-텍스트, chip 등): `space-1` ~ `space-2`.
- 폼 필드 간, 카드 내부 블록 간: `space-2` ~ `space-3`.
- 패널 헤더-바디, 카드 상하 padding: `space-3` 안팎 (상하는 좌우보다 한 단계 작게).
- 패널·섹션 간 세로 gap: `space-3` ~ `space-4`. border나 bg-subtle이 분리를 담당하므로 공간은 좁게.
- 페이지 body padding: `space-4` ~ `space-6`.

**랜딩·마케팅·에디토리얼 (선언형 UI)**
- 선언 섹션 간: `space-10` ~ `space-16`.
- 페이지 최상단·히어로 상하 호흡: `space-16` 이상.
- 큰 타이틀-서브헤드 간: `space-4` ~ `space-6`.

**공통 규칙**
- 어느 리듬이든, **카드·패널 그리드(border·bg로 이미 구분된 요소)의 가로/세로 gap은 균일하게.** 가로 `space-3`이면 세로도 `space-3`.
- 어느 리듬이든, 선언 섹션(히어로)과 콘솔 섹션(테이블/리스트)을 **같은 화면에서 섞을 때는 콘솔 리듬을 베이스로 두고** 선언 섹션 하나만 큰 호흡을 허락한다. 반대로 하지 않는다 (화면 전체가 랜딩처럼 뜨고 머리가 비게 됨).

**카드·패널 내부 padding — 시각적으로 상하좌우 동일**
- 카드, 패널, 모달, Callout 같은 "닫힌 박스" 안쪽은 **상하좌우 padding이 시각적으로 같아 보이게** 쓴다. 기본은 네 면 같은 토큰(`padding: var(--space-N)` 하나).
- 폰트는 line-height 여백을 품으므로, 콘텐츠가 큰 텍스트 블록이면 **상하를 수치상 한 단계 줄여** 시각 균형을 맞춘다 (line-height 보정). 예: 큰 타이틀 위주 카드면 `var(--space-2) var(--space-3)`. 이건 "비대칭을 쓰려는 게 아니라, 눈에 같아 보이게 하는 보정".
- 리스트 row·테이블 row처럼 **반복되는 가로 긴 아이템**도 동일 원칙 — 기본은 정사각, 큰 텍스트가 들어가면 line-height 보정으로만 상하 한 단계 축소.
- 예외는 panel 헤더(한 줄 고정 높이) 정도. 그 외엔 **"비대칭 padding이 눈에 보이면 틀린 것"**.

### Don't
- 스케일 밖의 임의 px 사용 금지. 필요하면 디자인 재검토 신호.
- 인접 스케일을 나란히 반복 금지 — 위계가 사라짐. 최소 2단계 차이. (line-height 보정은 예외)
- 컴포넌트 간 간격을 `space-2` 이하로 좁히기 금지 — **단, 버튼↔버튼·칩↔칩 등 "작은 컴포 묶음"은 역으로 `space-1`(4px) 고정.** 큰 섹션 간은 좁히지 말고, 작은 묶음은 넓히지 말라.
- 카드 그리드의 세로 gap을 가로 gap보다 크게 잡지 않는다 — 격자가 세로로만 벌어져 "열은 붙고 행은 떨어진" 어긋남이 생긴다.
- 카드 그리드끼리 또는 카드 그리드와 다음 패널을 `space-6` 이상 gap으로 분리하지 않는다 — 카드가 이미 border/배경으로 분리돼 있어 과한 공간은 "구조가 끊겨 보이는" 결과를 만든다.
- 카드·패널 내부 padding을 눈에 띄게 비대칭으로 쓰지 않는다 — 상하좌우가 시각적으로 같아 보이는 게 디폴트. 비대칭을 쓰는 경우는 "line-height 여백 보정" 목적일 때만, 상하를 한 단계 줄이는 쪽으로.
- **두 요소 사이 공간을 양쪽에서 동시에 잡기 금지 (이중 여백 금지).** 부모의 `gap` 과 자식의 `padding-top`/`margin-top` 을 동시에 쓰지 말 것. 둘 중 **한 쪽만** 공간 책임자다. 판정 기준: 두 블록이 **각자 독립된 "닫힌 박스"**(헤더 박스 + 콘텐츠 박스처럼 자체 padding 을 들고 다님)라면 **부모 gap = 0**, 두 블록이 **같은 트랙 안의 자식**(동일 패널 안 섹션들)이라면 **자식 padding = 0 + 부모 gap 으로 리듬**. 이걸 섞어 쓰면 공간이 두 번 더해져 리듬이 깨지고, 디자인 축을 바꿔도 한쪽만 반응해 어긋난다.

### Fallback
관련성이 확실치 않으면 `space-4`부터 시도.

### 관련
- [[axes/density]] — `--space-scale`로 모든 spacing 값 스왑

### 토큰 표
토큰에는 **고정 용도가 없다.** 아래 "전형적인 자리"는 가장 자주 쓰는 예시일 뿐, "섹션 간은 반드시 space-8" 식으로 못박지 않는다. 어느 자리에 어느 스케일을 쓸지는 위의 Do(앱 리듬 vs 랜딩 리듬)에서 결정한다.

| Token | 전형적인 자리 (예시) |
|---|---|
| `space-0.5` | 아이콘-텍스트 미세 간격 |
| `space-1` | 텍스트-아이콘, 아이콘 묶음, **버튼↔버튼 gap(고정)** |
| `space-1.5` | 컨트롤 내부 gap |
| `space-2` | 작은 gap (컴포넌트 사이는 제외 — space-1 고정) |
| `space-2.5` | 버튼 md 좌우 |
| `space-3` | 카드 내부, 콘솔 패널 세로 리듬 |
| `space-4` | 콘솔 패널 좌우 padding, 카드 그리드 gap |
| `space-5` | 콘솔 body padding |
| `space-6` | 콘솔 body padding (넉넉) / 랜딩 요소 간 |
| `space-8` | 선언 섹션 상하 호흡 |
| `space-10` | 랜딩 섹션 간 |
| `space-12` | 랜딩 섹션 간 (넉넉) |
| `space-16` | 랜딩 히어로·페이지 최상단 |

### 전역 element selector로 padding/margin 걸지 않기
`section`, `article`, `main`, `h1~h6` 등 **element selector에 전역 padding/margin을 걸면 그 태그를 쓰는 모든 자리를 오염**시킨다. 특히 `section`은 CTDS에서 "panel/카드 하나"를 뜻하는 자리로도 쓰이고 "docs의 스크롤 네비 섹션"으로도 쓰이므로, 두 자리의 리듬이 서로 다른 걸 하나의 전역 룰로 묶으면 반드시 한 쪽이 터진다.

- 전역 룰은 **특정 wrapper 클래스 안으로 scope**한다 — `section` ❌ → `.docs section` ✅.
- 섹션 간 호흡은 **부모 flex-column의 `gap`으로** 담당하고, 섹션 자체에는 padding을 걸지 않는 쪽을 선호.
- 디버깅 체크리스트: 어떤 자리의 패딩이 "내가 안 걸었는데 들어있다"면 **상위 globals.css의 element selector 규칙**부터 의심한다.

### 텍스트 gap·line-height
- **섹션 타이틀(h1~h3)에는 반드시 명시적 `line-height` 지정.** 지정 없으면 body base(1.5)를 상속해 큰 폰트에서 "위가 뭉텅 비어 보임" 함정이 발생한다. 큰 선언형은 `--lh-tight`(1.2), 패널 헤더는 1.3 안팎.
- 상하좌우 균일 padding의 함정: 모달 상단 텍스트(타이틀), 하단 버튼일 때 균일 padding이면 위가 넓어 보일 수 있다 — 이 때는 **먼저 타이틀의 line-height를 조이고**, 그래도 위가 뜨면 상단 padding을 한 단계 축소.
- 텍스트 ↔ 텍스트 gap: 두 요소 모두 line-height를 품으므로 보수적으로. 라벨-값은 `space-1~2`.
- 텍스트 ↔ 그래픽 gap: 그래픽은 line-height 여백이 없으므로 표준 스케일 그대로.
- 그래픽 ↔ 그래픽: 필요하면 한 단계 크게.

### 한 줄에 크기가 다른 요소 수직 정렬
한 flex row 안에 폰트 크기가 다른 두 요소(큰 숫자값 + 작은 라벨/[[components/badge]]/작은 아이콘 등)가 나란히 올 때, `align-items`는 다음 기준으로 선택한다. 임의 기본값(특히 `baseline`) 금지.

- **기본은 `center`.** 큰 글자와 작은 글자/배지의 중심을 맞춘다. 카드 안에서 "값 + 변화량 Badge" 같은 조합이 전형. baseline으로 맞추면 작은 요소가 아래로 쏠려 위쪽 패딩이 비어 보이고 카드 내부 균형이 깨진다.
- **같은 폰트 크기의 텍스트끼리** 가로로 나열될 때만 `baseline`. 다른 크기 섞이면 금지.
- 아이콘 ↔ 텍스트는 `center` 고정 (아이콘엔 baseline이 없다).
- 패딩이 균일한 카드 안의 row는 `align-items: center` + 균일 padding으로 "실제로도, 시각적으로도" 가운데 정렬이 성립한다. 큰 요소 하나 때문에 상하 여백이 어긋나 보이면 **패딩이 아니라 정렬을 의심한다.**
