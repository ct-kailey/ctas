# vara 대시보드와 현재 AINS 통합

## 기준

- ctas main 시작점: `8762e56`
- 반영한 vara: `2430f3186349dc6cae213d3a65389d34c575894c`
- 기존 작업본: AINS 0.1.0, 2026-10-13의 로컬 작업실·26개 DB 마이그레이션·8단계 프리뷰

vara의 커밋 이력과 기획 문서, `ains-dashboard` 구조를 보존하고 기존 플랫폼 소스를 루트에 통합했다. 기존 고객 데이터와 실행 기록은 코드에서 제외했다.

## 접속과 빌드

`/`는 기존 인증된 작업실, `/preview`는 전체 흐름, `/dashboard/`는 vara 대시보드다. 작업실·로그인·워크플로우 프리뷰에서 대시보드로 이동할 수 있고 대시보드에서도 돌아갈 수 있다.

Next 대시보드는 `basePath: '/dashboard'`와 정적 내보내기를 사용한다. 프로젝트 상세·설정의 예시 경로도 빌드 시 생성된다. 루트 빌드는 두 앱의 결과를 `dist/`에 합치며 Express가 `/dashboard` 아래의 정적 라우트를 먼저 처리한다. 알 수 없는 대시보드 주소는 404이며 기존 작업실 화면으로 잘못 연결하지 않는다.

Next의 인라인 초기화 스크립트는 내보낸 HTML의 정확한 SHA-256 해시만 CSP에 허용한다. 기존 작업실·API의 스크립트 정책은 변경하지 않는다. 소스 파일을 쓰는 개발용 CTDS 온보딩은 정적 대시보드에서 실행하지 않는다.

## 예시 동작의 범위

vara의 알림함·결정 기록·자료 넣기·메일 초안·프로젝트 설정은 mock 데이터 기반이다. 기존 AINS API에 연결하거나 실제 프로젝트를 덮어쓰지 않는다. 명시적인 프리뷰 안내를 표시하며, 자료 입력·확인·처리 상태는 새로고침하면 초기화된다. 실제 업무 처리는 기존 작업실에서 진행한다.

프리뷰와 실제 업무 데이터를 연결하려면 프로젝트 ID·권한·결정 승인·자료 버전·질문 대기 상태를 각 실제 API 계약에 맞춰 매핑하는 별도 구현이 필요하다.

## 검증 방법

- 기존 Node·PostgreSQL 회귀 테스트와 Python 추출 테스트
- `/dashboard` 직접 접속·상세 경로 새로고침·RSC 정적 응답·자산 경로
- 인라인 CSP 허용, 기존 `/preview` CSP 유지, 숨김 파일·미등록 경로 차단
- 대시보드 자료 넣기·알림 처리·프로젝트 탭·설정과 기존 화면 왕복
- CTDS 토큰 검사와 두 앱의 production build

운영 배포와 실계정 연동은 위 로컬 검증과 별도로 수행한다.
