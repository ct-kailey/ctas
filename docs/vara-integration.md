# vara 디자인·알림과 기존 AINS 전체 업무 흐름 통합

## 통합 범위

- ctas main 시작점: `8762e56`
- 반영한 vara: `2430f3186349dc6cae213d3a65389d34c575894c`
- 기존 플랫폼: AINS 0.1.0, 26개 DB 마이그레이션과 8단계 워크플로우 프리뷰

vara의 커밋 이력·기획 문서·화면 구조와 기존 플랫폼 소스를 함께 보존한다. 사용자에게 제공하는 운영 앱은 기존 React/Vite 작업실 하나다. 이 앱 안에 vara의 디자인·업무 홈·알림 표현을 반영하고 기존 계약·기획부터 구현·검수·유지보수까지의 기능을 이어간다. 별도 DB를 만들거나 기존 자료를 다시 등록하지 않는다. 운영 시 기존 앱 서비스의 DB 연결과 설정을 유지한다.

## 화면 경로

| 경로 | 역할 |
| --- | --- |
| `/`, `/?tab=home` | 기존 작업실 안의 실제 프로젝트 업무 홈 |
| `/?tab=alerts` | 같은 프로젝트의 알림·검토 현황 |
| `/?project=<ID>&tab=<탭>` | 계약·기획, 문서, Context, 실행·검수 등 기존 업무 화면 |
| `/preview` | 기존 8단계 전체 워크플로우 안내·체험 |

프로젝트 목록은 현재 계정의 접근 권한으로 조회한다. 조회 중·비로그인·빈 프로젝트·권한 없음·조회 실패를 구분하며, 오류가 발생해도 예시 데이터를 실제 자료처럼 표시하지 않는다. `ains-dashboard/`는 참고·보존 소스이고 운영 앱으로 빌드하거나 제공하지 않는다.

### 이전 대시보드 URL 호환

- `/dashboard`, `/dashboard/` → `/?tab=home`
- `/dashboard/alerts`, `/dashboard/alerts/` → `/?tab=alerts`
- `/dashboard/example/`, 예전 `seegene`·`a-corp`·`b-corp` 프로젝트 및 설정 경로 → `/?tab=home`
- `project` 쿼리가 명시되면 값이 비어 있거나 잘못되어도 그대로 보존한다. 작업실에서 접근 권한을 검증하며, 임의의 다른 프로젝트로 치환하지 않는다.
- 예시 경로의 프로젝트 슬러그를 실제 프로젝트 ID로 해석하지 않는다.
- 나머지 경로·예전 Next 정적 자산은 404를 반환한다. GET/HEAD만 302 이동을 지원한다.

이동 대상은 서버가 정한 동일 출처의 상대 경로와 `URLSearchParams`로 조립한다. 임의 `redirect`·`tab` 입력이나 외부 URL로 이동하지 않는다. 응답은 `Cache-Control: no-store`이며 기존 CSP를 유지한다.

## 실제 데이터 조회

운영 업무 홈은 기존 `GET /api/projects/:p/overview`의 문서·분석·활동 현황과 신규 `GET /api/projects/:p/attention`의 확인할 업무를 함께 사용한다. 별도 Next 대시보드 API를 중심으로 업무 흐름을 다시 구성하지 않는다.

### 확인할 업무와 알림

`/attention`은 기존 세션 인증과 프로젝트 membership 검사 뒤에서 실행되며, SELECT 안에서도 membership을 다시 확인한다. 열람 권한도 조회할 수 있고, 회원이 아니거나 없는 프로젝트는 404를 반환한다. 응답은 `Cache-Control: no-store`다.

응답 형태는 `{items, counts: {all, urgent, check, info}, truncated}`다. 각 항목은 안정적인 `id`(`종류:원본 UUID`), `kind`, `grade`, `title`, `description`, 판단 기준 코드 `rule`, 원본 등록 시각 `created_at`, 이동할 업무 `tab`과 원본 식별자 `target`을 포함한다. 원문 본문·AI 입력·자격증명은 포함하지 않는다.

| 분류 | 원본 상태와 기준 |
| --- | --- |
| `urgent` · 긴급 | 문서·대화 분석의 `failed` / `uncertain`, 답변 기한이 지난 `waiting` 질문, `blocked` 또는 마감일이 지난 미완료 작업 |
| `check` · 확인 | 변경 검토 `needs_review` / `no_change`, Context 후보 `pending`, 질문 `draft` / `answered_pending`, 3일 이상 응답 대기, 채널 기록 `needs_review` |
| `info` · 참고 | 위 기한 초과·장기 대기에 해당하지 않는 `waiting` 질문 |

작업의 날짜 단위 마감은 서울 날짜 기준으로 판단하며, 오늘 마감은 초과로 보지 않는다. 답변이 도착한 `answered_pending` 질문은 과거 답변 기한이 지났더라도 답변 검토 대상으로 분류한다. 채널 원문 변경은 별도 기준 코드로 알리며, 긴급도는 해당 분석 상태를 따른다. 같은 원본 항목에 보류·마감 초과가 함께 발생해도 알림은 한 건이다.

한 번의 읽기 전용 SELECT로 동일한 DB 스냅샷의 목록과 집계를 계산한다. 목록은 긴급 → 확인 → 참고, 등록 시각 내림차순, ID 순으로 최대 100건을 반환한다. `counts`는 제한 전 전체 개수이며, 초과하면 `truncated: true`다. 업무 홈은 그중 우선 확인할 5건을 보여주고, 알림 화면은 분류별 조회와 원본 업무 목록 이동을 지원한다.

별도 알림 원장이나 읽음 상태를 만들지 않는다. 조회·클릭만으로 알림이 없어지지 않으며, 원본 업무에서 검토·질문·실패 등의 상태를 해결하면 다음 조회에 반영된다. 알림 확인과 승인·재처리·발송은 별개이며, 실제 조치는 기존 업무 화면의 권한과 검토 절차를 따른다. 조회는 DB 쓰기·AI 호출·메시지 발송을 실행하지 않으며 새 마이그레이션도 추가하지 않는다.

### 기존 요약 API 호환

`GET /api/projects/:p/dashboard`는 이전 연결과의 호환을 위해 유지하지만 현재 업무 홈의 조회 경로는 아니다. 동일한 인증·membership 검사 아래 문서·리비전·검토·분석 실패·Context·업무·질문·계약 문서의 전체 집계와 최대 6개씩의 최근 목록을 읽기 전용으로 반환한다.

## 같은 프로젝트에서 업무 이어가기

작업실은 `?project=...&tab=...`을 읽어 해당 프로젝트와 업무 화면을 연다. `action=upload`는 권한과 프로젝트 자료 조회가 완료된 뒤 등록창을, `action=new-project`는 프로젝트 생성창을 연다. 창을 여는 동작만으로 자료나 프로젝트가 저장되지는 않는다.

업무 홈과 각 화면 사이를 이동할 때도 현재 프로젝트 ID를 유지한다. 명시한 프로젝트가 없거나 권한이 없으면 다른 프로젝트를 대신 선택하지 않는다. 기존의 미저장 내용 확인 절차를 유지하며, 프로젝트 목록과 권한을 확인하기 전에는 해당 프로젝트의 상세 현황을 요청하지 않는다.

Google 로그인은 콜백이 `/`로 돌아오므로 로그인 직전의 허용된 프로젝트·탭·동작만 `sessionStorage`에 최대 15분간 보관해 한 번 복구한다. 외부 URL로 이동하는 값은 저장하지 않는다. 브라우저 저장소가 차단된 경우에도 로그인은 가능하지만 OAuth 목적지 복구는 생략된다. 이메일 재로그인 후에는 접근 가능한 명시적 프로젝트를 다시 선택한다.

## 업무 흐름 안내

`/preview`는 예시 데이터로 기존 전체 흐름을 이해하는 안내 화면이다. 실제 업무를 대신하는 별도 앱이 아니며 원문 저장·AI 실행·메일 발송을 하지 않는다. vara의 Next 원본과 이전 연결 구현은 저장소에 보존하지만 운영 라우트·이미지에는 포함하지 않는다.

## 빌드와 배포 구조

루트 `npm run build`는 Vite 앱 하나를 `dist/`에 생성한다. Vite의 `emptyOutDir` 설정이 이전 정적 결과를 정리하므로 오래된 Next 파일을 다시 제공하지 않는다. `Dockerfile`은 루트 의존성과 기존 웹 소스만 빌드하며 Next 패키지를 설치하거나 `ains-dashboard/`를 복사하지 않는다.

Express는 `/dashboard` 호환 이동을 기존 SPA 정적 파일보다 먼저 처리한다. 인라인 Next 스크립트용 CSP 해시를 추가할 필요가 없으며 기존 스크립트 정책을 그대로 유지한다. API·PostgreSQL·작업자는 기존 구성을 사용한다.

개발 시에도 Vite의 `/dashboard` 프록시는 기존 API 서버의 3100 포트로 전달한다. 별도 3001 포트의 Next 서버가 필요하지 않다.

Railway는 기존 앱 서비스·PostgreSQL·서비스 변수를 유지한 상태에서 루트 Docker 이미지를 갱신한다. GitHub 반영과 운영 배포 완료는 별개다. 이 문서는 운영 배포 완료나 실제 Nora 실행 검증을 의미하지 않는다.

## 검증

실제 데이터 연결을 위해 다음 항목을 검증한다.

- 기존 데이터의 정확한 집계와 최근 6개 제한, 프로젝트 간 격리, 열람 권한, 권한 회수
- 원본 상태별 알림·답변 기한·서울 날짜 마감 판정, 해결 후 제거, 반복 조회 시 상태 유지, 100건 제한과 정확한 전체 집계
- 원문·세션 정보 비노출과 읽기 전용 트랜잭션에서의 요약 조회
- 같은 프로젝트로 이동, 유효한 프로젝트의 재로그인 복구, 잘못된 목적지 차단
- Google 로그인 목적지의 일회성·만료 처리와 브라우저 저장소 차단 시 로그인 유지
- 기존 인증·권한·CSRF·원문 다운로드, 이전 대시보드 URL 호환·CSP
- 기존 작업실 내 업무 홈·알림·전체 업무 화면, 안내용 프리뷰의 단일 앱 빌드와 화면 이동
