# AINS 전체 워크플로우 프리뷰

`/preview`는 `AINS_기획_및_구현_일정_개정본.docx`의 제품 구조와 MVP 완료 기준을 화면으로 검토하는 별도 React 진입점이다. 실제 작업실의 로그인과 프로젝트 API를 호출하지 않는다. 샘플은 모두 가상의 고객포털 사례이며 원본 고객 데이터나 첨부 문서 자체를 배포하지 않는다.

| 화면 | 검토할 흐름 | 문서 근거 |
| --- | --- | --- |
| 프로젝트 준비 | 기업·일정·저장소·계약 기준, 문서 에디터와 양식 보정 | 1장 목표·원칙 및 기존 계약 준비 흐름 |
| 자료 수집·검토 | 문서·메시지·회의·Git의 출처와 이력 속성, 사람의 원문 확인 | 5.1 Context Integration |

## 프리뷰의 경계

- 모든 작업은 브라우저 메모리의 예시 상태만 변경한다. 페이지 새로고침 또는 프리뷰 초기화로 돌아간다.
- 단계별 자유 탐색을 지원한다. 앞 단계를 생략하여 연 화면은 해당 단계의 시연 상황을 보여준다. 실제 end-to-end 상태 머신이나 백엔드 완료 여부를 나타내지 않는다.
- 방문한 단계는 숨김 상태로 유지해 왕복 시 편집한 내용을 보존한다. 단계별 완료 표시는 프리뷰 체험 진행률이다.
- AI·CLI 실행, 검색, 문서 생성, 질문·답변, 메시지 발송, 권한 적용은 고정된 샘플과 로컬 상태 변화다. 실제 실행 자격 증명, 셸, 외부 채널, LLM을 사용하지 않는다.
- 개인 CLI가 오프라인·미설치·인증 오류일 때 실행을 막고, 사용자가 실행 대상을 바꾸거나 상태를 복구하는 장면을 체험한다. 브라우저에서 로컬 CLI를 실제 실행하지 않는다.
- Web/React UI를 바탕으로 한 Desktop 실행 환경의 미리보기다. Electron/Tauri 패키징 및 실제 CLI 어댑터 구현을 의미하지 않는다.
- 공통 화면 설정만 기존 CTDS 브라우저 테마 저장 방식을 사용한다.

## 구성

`main.jsx`에서 경로에 맞는 앱을 지연 로드한다. 프리뷰는 `workflow-preview.jsx`의 탐색·단계 안내·전체 흐름, `preview-context.jsx`, `preview-work.jsx`, `preview-support.jsx`로 나눈다. 각 모듈은 CTDS 어댑터와 자신의 CSS만 사용한다. 실제 작업실 상단과 로그인 화면에서 `/preview`로 이동할 수 있다.

검증 시 실제 API 호출이 없는지, 단계 왕복과 초기화, 사람의 확인 게이트, 정상/오류 실행, 보완→재실행 루프, 모바일 오버플로우, 기존 작업실 진입을 확인한다. CSS 토큰 검사와 production build를 함께 실행한다.
