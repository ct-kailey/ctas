# 수집한 대화를 업무로 연결하기

프로젝트의 **수집·검토함**에서 검토하여 등록한 대화를 유지보수·추가 요청 또는 기존 질문의 답변 후보로 연결한다. 카카오톡·Slack·메일 등 공통 수집기를 통과한 대화는 같은 절차를 사용한다.

## 사용 순서

1. 외부 채널을 연결하거나 대화를 직접 가져온다.
2. 수집 당시 원문을 대조하고 **문서·기록으로 등록**한다.
3. 등록한 대화의 **업무로 연결**에서 이번 요청 또는 답변에 해당하는 메시지만 선택한다.
4. 다음 중 하나를 선택한다.
   - **고객 요청으로 검토**: 요청 내용을 확인해 분류 검토안을 만든다. 연결된 검토에서 Nora 분석과 사람의 분류 확정을 진행한다. 기존 범위 내 유지보수·Bug Fix로 확정한 요청은 승인된 기획 기준선과 함께 구현 계획으로 연결한다.
   - **질문 답변으로 연결**: 현재 답변을 기다리는 질문을 선택한다. 본문·작성자·답변 시각을 대조하여 답변 후보로 등록한다. 담당자의 최종 답변 확인 전까지 연결 작업은 대기 상태를 유지한다.
5. 연결 이력에서 해당 요청 분류 또는 질문으로 바로 이동한다.

이 기능은 질문 발송, 코드 실행, Main Context 확정을 자동으로 실행하지 않는다. 기존 업무별 승인 절차를 이어서 사용한다.

## 원문과 결정 이력

- 연결할 때 수집 항목·선택 메시지·원문 해시·검토한 본문·담당자·시각·대상 기록을 보존한다.
- 메시지 작성자는 채널 원문에 표시된 이름이다. 외부인의 실제 신원이나 승인 권한을 검증했다는 의미는 아니다.
- 원본 시각이 있으면 해당 시각을 사용한다. 시각이 없는 원문은 담당자가 확인해 입력하며, 원문 시각을 임의로 수집 시각으로 대체하지 않는다.
- 같은 연결 요청을 다시 제출해도 중복 기록을 만들지 않는다. 다른 내용에 동일 요청 식별자를 재사용하면 거부한다.
- 이미 답변 검토 중이거나 확정된 질문을 이 기능으로 덮어쓰지 않는다.

## 원문이 변경되면

원문이 수정·삭제되거나 출처 버전이 달라지면 해당 수집 항목으로 새 업무를 연결할 수 없다. 최신 원문을 다시 수집하고 검토한다.

답변을 기록한 뒤 원문이 바뀌면 답변 확정 시 다시 검증한다. 이미 확정한 답변의 이력은 그대로 보존하되 현재 승인 근거로 사용할 수 없음을 표시한다. 그 답변을 인용한 Main Context에도 변경 상태가 전달된다.

작업을 막는 질문의 확정 근거가 변경되면 연결 작업의 진행·검수 게이트를 다시 막는다. **후속 확인 질문 만들기**에서 사유를 남기면 새 질문 초안을 만들고 담당자·수신자·채널·연결 작업을 이어받는다. 이전 답변·질문 시각·결정 이력은 덮어쓰지 않는다.

후속 질문은 실제 질문한 이력을 기록하고, 최신 답변과 현재 유효한 출처를 연결한 뒤 담당자가 확정해야 작업 대기가 해제된다. 후속 질문을 만들거나 취소한 것만으로 차단이 해제되지는 않는다. 후속 질문의 답변도 원문이 바뀌면 다시 확인해야 한다. 이전 Main Context 기록은 그대로 남으므로 새 결정을 반영할 때 별도로 대체 관계를 검토한다.

## 매칭 범위

현재 수집 데이터만으로는 모든 제공사의 스레드·답장 관계를 확인할 수 없다. 동일 채널이나 비슷한 문구만으로 실제 답변이라고 확정하지 않으며, 담당자가 연결할 질문과 메시지를 선택한다. 이 화면의 질문 목록은 연결 가능한 대기 질문 목록이다.

## API

프로젝트의 기존 세션·권한·CSRF 검증을 사용하는 경로다. 조회는 프로젝트 구성원, 연결은 소유자·검토자가 수행한다.

| 메서드 | 경로 | 결과 |
|---|---|---|
| GET | `/api/projects/:p/channel-inbox/:id/workflow` | 사용 가능한 원문, 대기 질문, 기존 연결 이력 |
| POST | `/api/projects/:p/channel-inbox/:id/workflow/classification` | 근거가 고정된 분류 검토안 |
| POST | `/api/projects/:p/channel-inbox/:id/workflow/answer` | 기존 질문의 검토 대기 답변 |
| POST | `/api/projects/:p/questions/:id/follow-up` | 근거가 변경된 확정 질문의 후속 확인 초안 |

공통 입력은 `request_id`, `source_sha256`, 선택한 불변 메시지 UUID 배열 `event_ids`, 확인한 본문 `text`, `acknowledge_evidence: true`다. 답변 연결은 `question_id`, `expected_question_version`, `responded_by`, `responded_at`도 필요하다. 메시지 ID·출처 해시는 서버에서 조회한 값을 사용한다. 실제 외부 메시지 ID와 내부 불변 이벤트 UUID를 혼동하지 않는다.

연결과 대상 기록 생성은 같은 DB 트랜잭션에서 처리한다. 분류 검토안에는 승인된 수집 근거가 연결되고, 질문 답변에는 원문 출처가 추가된다. 네트워크 응답을 받지 못한 경우 같은 요청을 재제출하거나 연결 이력을 확인한다.

후속 질문 생성에는 `request_id`, `expected_version`, `reason`을 전달한다. 같은 요청은 같은 질문을 반환하며, 취소되지 않은 후속 질문이 있으면 중복 생성하지 않는다. 연결 관계와 생성 사유는 별도 불변 이력에 저장한다. 후속 질문의 답변 확정에는 최신 출처가 최소 한 개 필요하다.
