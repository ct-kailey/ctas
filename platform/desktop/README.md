# CTAS Desktop

CTAS의 로컬 개발 실행기입니다. Railway의 웹 서비스와 별도로 실행하는 Tauri 2 앱이며, 기존 CTDS 컴포넌트와 카키 테마를 사용합니다.

## 현재 제공하는 기능

- 네이티브 폴더 선택기로 로컬 Git 저장소 선택
- 프로젝트 식별자, GitHub 저장소, 선택한 개발 도구를 기기에 저장
- Git origin과 대상 저장소 일치 여부, 브랜치, 커밋, 미커밋 변경 확인
- Git·Codex·Claude Code CLI의 설치 경로 및 버전 확인
- 사용자가 입력한 작업을 로컬 Codex 또는 Claude Code CLI로 실행하고 작업 내역·결과·diff 확인
- 프로젝트별 일회용 연결 코드로 CTAS 웹과 기기를 연결
- 수신을 켜 둔 앱에서 웹의 승인된 칸반 작업을 자동 수신
- 실행 상태와 실제 Git diff를 원래 Task에 동기화하고, 전송 실패 시 저장된 결과만 재전송
- 실행 중단, 실패 원인 표시, 앱을 다시 열었을 때 기록 조회
- 고정된 CTAS 서비스 주소를 시스템 브라우저로 열기

코드 수정은 선택한 저장소의 현재 커밋에서 만든 별도 작업 복사본에서 수행합니다. 원본의 미커밋 변경은 실행 입력에 포함하지 않습니다. 자동 커밋·push·PR 생성·merge는 제공하지 않습니다. 설치된 CLI는 사용자의 기존 로그인 정보를 사용하며 앱 화면에서 인증 키를 입력받지 않습니다. 버전 확인만으로 로그인 성공을 표시하지 않습니다.

두 CLI 모두 터미널에서 먼저 로그인해야 합니다. 앱은 실행 전 로그인과 필요한 CLI 기능을 점검합니다.

## Nora와의 관계

로컬 Codex·Claude Code 실행과 **Nora SDK 연결은 서로 다른 상태**입니다. 이 앱은 Nora의 비공개 desktop relay 프로토콜을 구현하거나 연결 완료를 가장하지 않습니다. Nora 워크스페이스 ID는 프로젝트 연결 범위를 확인하는 선택 정보입니다.

CTAS 웹의 작업 대기열을 HTTPS로 조회하는 별도 연결입니다. Nora가 분석한 정책과 Task, 사용자가 확인한 실행 범위가 CTAS 서버를 거쳐 앱에 전달됩니다. Nora SDK 실행 모드와 CTAS 데스크톱 실행 모드는 구분되며, 이 앱의 연결이 Nora MCP의 `get_local_sdk_connections`에 표시되지는 않습니다.

연결 구조:

1. Nora: 프로젝트 Context와 정책 분석, Task 생성
2. CTAS 웹: 실행 기기 선택, 칸반 시작 요청, 질문·임시 구현 동의와 근거 검증
3. CTAS 서버: 해당 프로젝트·저장소·기기에 한정된 작업 배정
4. Tauri 앱: 별도 작업 복사본에서 CLI 실행, 상태와 diff 수집
5. CTAS 웹: 원래 Task에서 결과 검토. 로컬 diff는 검증 전 결과이며, PR·CI·프리뷰 확인과 병합 승인은 별도 절차

## 웹에서 개발 시작하기

1. 앱에서 대상 Git 저장소 폴더를 선택하고 CTAS 프로젝트 ID·저장소·개발 도구를 저장합니다.
2. CTAS 웹의 프로젝트 자동화 설정에서 데스크톱 연결 코드를 발급합니다. 프로젝트 소유자만 코드를 발급하거나 기기를 해제할 수 있습니다.
3. 앱에 코드를 입력해 연결합니다.
4. 웹에서 개발 실행 방식을 CTAS 데스크톱으로 선택하고 기기와 도구를 저장한 뒤, 앱에서 자동 수신을 켭니다. 실행 설정 변경 전 생성된 Task는 최신 설정으로 정책을 다시 분석해야 할 수 있습니다.
5. 칸반 Task를 진행 중으로 옮깁니다. 고객 확인 사항이 남아 있으면 기존 검토·임시 구현 동의 절차를 거칩니다.
6. 앱이 작업을 받아 실행합니다. 웹의 AI 개발 화면에서 상태와 결과를 조회합니다.

앱이 꺼져 있거나 수신이 꺼져 있으면 작업은 대기합니다. 웹의 앱 열기는 `ctas://open?project=…` 링크를 사용하므로 설치된 앱과 브라우저의 외부 앱 열기 허용이 필요합니다. 링크에는 작업 명령이나 인증 정보를 넣지 않으며, 링크를 여는 것만으로 새 작업을 승인하지 않습니다.

연결 코드는 10분 동안 한 번 사용할 수 있습니다. 발급 후 다른 사람에게 공유하지 마세요. 실제 기기 인증 정보는 macOS 키체인에 저장되며 브라우저·React 상태나 결과 파일·로그로 전달하지 않습니다. 키체인 접근에 실패하면 자동 수신을 보류합니다.

## 연결이 끊겼을 때

- 작업을 받기 전: 앱이 다시 연결되면 대기 중인 작업을 조회합니다.
- 실행 중: 같은 작업을 자동으로 다시 실행하지 않습니다. 연결 상태를 갱신하고, 서버에서 실행 여부를 확정할 수 없으면 확인 필요 상태로 표시합니다.
- 실행 완료 후 전송 실패: 결과를 기기에 보관하고 동일한 결과 전송만 재시도합니다.
- 연결 해제·권한 회수로 전송이 거부됨: 로컬 결과를 보관하고 자동 수신을 중지합니다. 새 연결이 필요한 경우 웹에서 코드를 다시 발급합니다.
- 앱 종료·중단: 실행 프로세스를 정리하고 중단 기록을 남깁니다. 새 실행을 자동으로 만들지 않습니다.
- 저장소·프로젝트·실행 기기 변경: 기존 연결 범위를 그대로 다른 프로젝트에 사용하지 않습니다.

CLI 종료 코드가 0이라는 사실은 요구사항 충족이나 테스트 통과를 뜻하지 않습니다. 별도로 확인하지 않은 테스트·CI·프리뷰 상태는 통과로 기록하지 않습니다. 로컬 결과만으로 기본 브랜치에 자동 병합하지 않습니다.

## 실행

macOS에서 Node 22.12 이상, Rust stable, Xcode 개발 도구가 필요합니다. 개발에 사용할 Codex 또는 Claude Code CLI를 설치하고 먼저 로그인하세요.

```sh
npm ci
npm run desktop:dev
```

화면만 브라우저에서 확인하려면 `npm run desktop:web`을 사용합니다. 브라우저에서는 네이티브 명령을 호출하거나 코드를 실행할 수 없습니다.

앱 빌드:

```sh
npm run desktop:build
```

현재 macOS `.app` 빌드 대상입니다. 기본 출력은 `src-tauri/target/release/bundle/macos/CTAS Desktop.app`이며, 체크아웃 경로에 `:`가 있으면 실행 스크립트가 Cargo 출력만 시스템 임시 디렉터리의 `ctas-desktop-target`으로 옮깁니다. 빌드 완료 시 실제 출력 경로를 표시합니다. 외부 배포용 Apple 서명·공증은 별도 설정이 필요합니다.

## 검증

```sh
node --test platform/tests/desktop-bridge.test.js
npm run check:ctds
npm run desktop:build:web
npm run desktop:test
```

일반 테스트는 실제 모델을 호출하지 않습니다. 다음 검증은 새로운 임시 Git 저장소에서 실제 Codex 계정을 사용해 파일 생성·diff·원본 보존을 확인합니다.

```sh
CTAS_DESKTOP_LIVE_CODEX=1 npm run desktop:test -- --lib live_codex_smoke_isolated_fixture -- --ignored
CTAS_DESKTOP_LIVE_CLAUDE=1 npm run desktop:test -- --lib live_claude_smoke_isolated_fixture -- --ignored
```

기기 연결과 서버 작업 배정 테스트는 테스트 DB의 임시 스키마와 합성 데이터를 사용합니다. 운영 프로젝트에서 실제 개발을 시작하는 검증과 구분합니다.

개발 모드에서도 경로에 `:`가 있으면 Vite의 파일 접근 검사를 유지한 채 공개 프런트엔드 소스만 임시 경로에 복사하며, 수정사항을 반영합니다. 인증 정보나 `.env`는 복사하지 않습니다.

## 네이티브 경계

- 네이티브 명령은 번들된 `main` 창에만 허용합니다. 외부 웹 페이지에는 IPC를 허용하지 않습니다.
- 작업 폴더는 네이티브 선택값을 사용합니다. JavaScript에서 임의 경로·실행 파일·shell 명령을 전달받지 않습니다.
- 실행할 GitHub 저장소와 HEAD를 시작 시 다시 확인합니다.
- 저장소 복사본은 작업 분리 용도입니다. 각 CLI의 제한 실행 모드와 sandbox를 함께 사용하며, 필요한 기능이 없는 CLI에서는 실행을 시작하지 않습니다.
- 웹 요청은 프로젝트에 연결된 기기로만 배정합니다. 기기 연결·작업 요청자의 권한과 승인한 저장소·커밋을 실행 전 다시 확인합니다.
- 네이티브 연결은 고정된 CTAS HTTPS 주소만 사용합니다. 기기 토큰은 브라우저 세션과 별개이고 서버에는 해시만 저장합니다.
- 프로세스 시간·출력량에 상한을 두고, 원격 저장소로 자동 push하지 않습니다.
- 민감 파일은 diff 표시에서 제외하며 CLI의 인증 정보를 UI나 서버로 복사하지 않습니다.

현재 실행기는 GitHub 원격 주소를 가진 로컬 저장소를 지원합니다. 추적 중인 인증 파일, 프로젝트 CLI 설정(`.codex`·`.claude`·`.mcp.json`), 심볼릭 링크 또는 서브모듈이 있으면 실행 전에 중단합니다. `.npmrc`는 인증·네트워크 설정이 없는 허용된 단순 옵션만 지원합니다. 의존성 자동 설치는 하지 않으므로 별도 복사본에 필요한 의존성이 없으면 테스트 미실행 사유가 결과에 남을 수 있습니다. 실행 완료와 테스트 통과는 구분해서 검토합니다.
