# 로그인 없는 공유 열람

프로젝트 관리자는 로그인하지 않은 검토자에게 만료 시간이 있는 링크를 전달할 수 있습니다. 공유받는 사람은 선택한 프로젝트의 현재 문서·알림·요구사항·업무 현황을 조회합니다. 실제 담당자의 로그인 세션이나 비밀번호를 공유하지 않습니다.

## 사용 방법

1. 관리자 계정으로 접속해 **공유**를 엽니다.
2. 공유할 프로젝트를 선택하고 이름과 만료 기간을 확인합니다. 최대 7일 동안 공유할 수 있습니다.
3. 발급된 링크를 복사해 전달합니다. 링크 원문은 발급할 때만 표시합니다.
4. **공유** 목록에서 링크를 종료할 수 있습니다. 포함된 프로젝트 모두를 관리하는 다른 관리자도 종료할 수 있습니다.

공유받는 사람은 전체 링크를 열면 됩니다. 로그인 화면이나 이전 공유 화면이 이미 열린 탭에 링크를 붙여 넣어도 공유 접속을 다시 시작합니다. 접속 후 주소창에서는 공유 코드가 제거되므로, 다른 사람에게 전달할 때는 발급 시 복사한 원래 링크를 사용합니다.

공유 대상 프로젝트의 문서가 갱신되면 공유 화면에도 새 내용이 표시됩니다. 공유를 발급한 뒤 담당자에게 새로운 프로젝트가 추가되어도 기존 링크의 공유 범위는 자동으로 넓어지지 않습니다.

등록·수정·승인·AI 실행·프로젝트 생성은 공유 화면에서 제공하지 않습니다. 계정·연동 설정과 원본 파일·음성·코드 패치 다운로드도 제한합니다. 이미 화면에 표시된 내용은 링크 종료로 회수되지 않지만, 종료 후 추가 조회는 거절됩니다.

## 권한과 세션

- 공유 링크마다 로그인할 수 없는 전용 열람 사용자를 생성하고, 선택한 프로젝트의 `viewer` 권한만 부여합니다. 일반 구성원 목록에는 이 시스템 사용자를 표시하지 않습니다.
- 링크 발급자는 포함된 모든 프로젝트의 관리자여야 합니다. 화면 기준이 되는 계정도 해당 프로젝트의 구성원이어야 합니다. 두 조건은 조회 시마다 다시 확인합니다.
- 별도 공유 쿠키를 사용합니다. 기존 로그인 쿠키를 다른 사람에게 전달하거나 담당자 계정으로 실행하지 않습니다.
- 공유 세션은 DB의 링크 만료·종료 상태로 권한을 판단합니다. 만료된 공유에서 기존 개인 계정으로 자동 전환하지 않도록 공유 모드 표시는 더 오래 유지하며, **공유 열람 종료** 또는 정상 로그인 시 해제합니다.
- 기본 조회 권한에 더해 API 허용 목록을 적용합니다. 비용이 발생하는 의미 검색, 데이터를 저장하는 Daily Brief 등의 GET도 공유 세션에서는 실행하지 않습니다.
- 담당자 관점의 ‘내 작업’과 질문 리마인더는 선택된 프로젝트 안에서만 표시합니다. 원래 담당자의 ID는 조회 조건으로만 사용하며, 서버에서 담당자의 수정·승인 권한을 사용하지 않습니다.

## API

| API | 용도 |
| --- | --- |
| `GET /api/shared-views` | 현재 계정이 관리할 수 있는 링크 조회 |
| `POST /api/shared-views` | 선택한 프로젝트의 링크 발급 |
| `POST /api/shared-views/:id/revoke` | 링크 종료 |
| `POST /api/auth/shared-view` | 공유 토큰으로 별도 열람 세션 시작 |
| `POST /api/auth/shared-view/exit` | 만료 여부와 관계없이 공유 열람 종료 |

발급 입력은 `project_ids`, `label`, `expires_in_hours`이며, 관리 도구에서 다른 담당자의 관점을 공유할 때는 `source_user_id`도 지정할 수 있습니다. 공유 대상은 발급 시 고정됩니다.

토큰은 충분한 난수로 생성해 DB에는 해시만 저장합니다. 링크의 `#share=` 부분은 브라우저가 HTTP 요청 경로나 Referrer로 전송하지 않으며, 화면은 토큰을 교환할 때 주소에서 제거합니다. 링크 원문을 일반 로그나 이력에 저장하지 않습니다.
