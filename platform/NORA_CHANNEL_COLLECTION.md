# Nora 커넥터 기반 기록 수집

## 사용 흐름

1. 프로젝트 설정에서 해당 프로젝트의 Nora 워크스페이스를 연결합니다.
2. Nora Settings에서 Slack·Discord·Drive 커넥터의 읽기 권한을 연결합니다.
3. AINS `자료·회의 → 업무 도구 연결`에서 `Nora 수집 연결`을 추가하고 채널/폴더 ID를 지정합니다.
4. 주기적 수집과 이벤트 수집의 사용 여부를 선택하고 `Nora 파이프라인 연결`을 누릅니다.
5. `지금 수집` 또는 일정/이벤트 실행으로 새 기록을 수집합니다.
6. `대화 검토함`에서 AI 문서 초안과 원문을 비교하고 업무 영역·기록 유형·결정일을 확인한 뒤 기록으로 등록합니다.

등록만으로 수집은 시작되지 않습니다. 설정 저장 시 AINS 적재는 중지되며, Nora에 적용해야 기존 원격 일정도 변경됩니다. 이미 시작된 원격 실행은 취소되지 않습니다. Nora에서 직접 관리 노드를 변경하면 AINS가 자동으로 덮어쓰거나 수집을 계속하지 않습니다.

## 실행 구조

- 일정 진입점: Nora `ingest_schedule` → 범위가 고정된 `src_cloud` → 문단 분할(`norm_chunk`, 자동 문서 유형 분석 끔).
- 이벤트 진입점: 인증된 AINS 이벤트 요청 → 내구성 큐 → Nora `trg_http_api` → 동일 범위 `src_cloud`.
- 공통 적재: 소스별 Nora Library 태그 → AINS의 원문 조회 → 변경·중복 검사 → 불변 원문 이력/검토함 → 프로젝트별 Nora 분석 → 사람이 검토 후 문서 등록.

두 파이프라인은 같은 Library 수집 대상을 사용합니다. 단일 플로우에 복수 트리거를 넣는다고 가정하지 않습니다. Nora의 수집 실행과 AINS의 결과 적재는 분리되어 있어, 실행 요청 접수는 문서 생성 완료를 뜻하지 않습니다. AINS는 준비된 원문을 주기적으로 확인합니다. 본문 추출 전인 문서는 Nora의 문서 단위 실행으로 추출하며, 추출 중에는 커서를 이동하지 않습니다. 추출 실패는 검토 필요 상태로 표시합니다.

## 이벤트 연결

수집 연결의 `이벤트 연결 키 발급`에서 해당 소스 전용 키를 발급합니다. 한 번만 표시되며 AINS에는 해시만 저장합니다. 재발급 시 이전 키는 즉시 무효화됩니다.

```http
POST /api/nora-channel-trigger/<source-id>
Authorization: Bearer <source-specific-key>
Content-Type: application/json

{"event_id":"upstream-unique-event-id"}
```

이 엔드포인트는 수집 실행을 깨우는 용도입니다. 원문, 커넥터 ID, 채널 ID, 실행할 코드, 임의 URL을 받지 않습니다. 같은 이벤트 ID를 재전송하면 같은 접수 결과를 반환합니다. 프로젝트·소스 권한 및 현재 이벤트 활성화 상태를 다시 검사합니다. 시간당 소스별 최대 120회 접수합니다.

Slack Events API 등의 구독·서명 검증 브리지는 별도로 연결해야 합니다. 이 기능만으로 Slack 앱의 이벤트 구독이 자동 등록되지는 않습니다. 브리지가 공급자의 서명을 검증한 뒤 위 엔드포인트에 이벤트 ID를 전달할 수 있습니다. 직접 브리지가 없다면 주기적 수집부터 사용합니다.

## 데이터와 검토

- Nora 문서 ID, 원문 본문, 채널/폴더 범위, 수집 시각, 원본에서 제공하는 시각·작성자·링크를 보존합니다.
- Nora Library에서만 제공하는 `updated_at`은 Library 문서 변경 시각입니다. 고객 발언 시각이나 결정일로 대체하지 않습니다.
- 현재 Library 조회에 원본 작성자·발언 시각·링크가 없으면 미제공으로 표시합니다. 자동 추론한 결정 사항은 확정 사실이 아닙니다.
- 같은 문서 ID와 내용은 일정/이벤트 양쪽에서 읽혀도 중복 적재하지 않습니다. 변경본은 별도 원문 이력이며 기존 검토의 근거가 바뀌었음을 표시합니다.
- 18,000자를 넘는 원문은 순서가 표시된 부분으로 나누어 보존합니다. AI가 원문을 명령으로 실행하지 않으며, 기존 검토함에서 각각 확인할 수 있습니다.
- 원본 시스템에서 삭제된 기록을 Nora가 명시적으로 전달하지 않으면 자동 삭제로 간주하지 않습니다. Nora Library 조회에서 잠시 사라진 것만으로 과거 이력을 지우지 않습니다.
- 분석은 문서 초안까지만 생성합니다. 검토자의 등록 이전에 확정 정책/Main Context로 병합하거나 고객에게 메시지를 보내지 않습니다.

## 장애 처리

- Nora 인증 만료/권한 회수: 원문을 조작하지 않고 오류를 표시하며, 재인증 후 다시 확인합니다.
- 추출 미완료·원문 변경·일시 오류: 커서를 전진하지 않고 재시도합니다.
- 부분 적재 후 실패: 결정적 이벤트/배치 ID로 이미 저장한 원문을 중복 생성하지 않습니다.
- 작업 리스 만료·실행 응답 불명: 실행 내역을 `uncertain`으로 남기고 실행 요청을 무조건 재전송하지 않습니다.
- 프로젝트별 권한과 Nora 워크스페이스, 관리 파이프라인 구성, Library 태그를 모두 확인합니다.

실제 Slack/Discord 데이터의 종단 검증에는 연결된 커넥터와 명시적으로 선택한 채널이 필요합니다. 공급자별 이벤트 구독 및 원문 메타데이터 전달 범위는 Nora 커넥터의 지원 범위에 따릅니다.
