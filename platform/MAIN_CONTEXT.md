# Main Context 구현·운영 기록

이 문서는 2026-10-12의 8개 기획 항목을 현재 코드와 대조한 결과다. `Main Context`는 하나의 거대한 프롬프트가 아니라 **프로젝트의 원문·검토 후보·확정 기록·결정 근거를 연결하는 검토 가능한 데이터 계층**이다.

## 기획 대조

| 기획 | 이번 반영 | 남은 범위 |
|---|---|---|
| 1. 프로젝트 Context 통합 | 문서 리비전, 계약 문서, 기능 작업, 승인된 채널 대화, Context 기록을 프로젝트·업무 영역·원문 근거로 연결 | 외부 도구의 자료는 실제 수집 설정 후 포함 |
| 2. 지속 수집 | 기존 문서/대화/작업 기록이 바뀌면 통합 조회에 반영. 회의·이미 변환된 STT 텍스트를 직접 기록 가능 | 범위 지정형 외부 커넥터·watch와 녹음 전사 구현. 실제 계정 연결 후 활성화 |
| 3. 과정과 판단 기록 | 판단 근거, 채택/폐기/보류한 대안, 질문·답변, 충돌 관계, 대체 이력. 같은 주제 키의 내용 변경을 충돌 후보로 감지 | 완료 작업에서 QA 근거·메모를 포함한 회고 작성 제안 자동 생성 |
| 4. 판단 가능한 정보 구조화 | Nora 분석으로 근거 인용, 요구사항·결정·질문·변경·충돌 분류. 고객 합의 상태와 계약 범위를 별도 저장 | 법적 계약 해석/고객 합의를 AI가 최종 확정하지 않음 |
| 5. 자료 탐색 | 프로젝트 내 통합 키워드 검색, 업무 영역/미확정 포함 필터, 원문 열기 | Gmail/Drive 범위 내 원격 검색과 OpenAI 임베딩 기반 의미+키워드 검색 구현. 연결 및 색인 시작 필요 |
| 6. Daily Timeline | 한국 시간 전일 09:00~당일 09:00 기본 구간, 날짜 선택, 페이지 조회, 발생 시각·등록 시각·시간 정확도 구분 | Daily Brief를 원문 연결과 함께 자동 집계. 외부 발송은 설정하지 않음 |
| 7. 가벼운 검토·확정 | 읽기는 승인 불필요. 후보 편집·명시적 재검토·승인/반려. 원문/기준 변경과 필수 미답변·미해결 충돌 시 반영 차단 | Nora 승인과 프로젝트 기준 반영은 역할이 다른 두 단계 |
| 8. 조직 지식 재사용 | 검토한 프로젝트 지식 저장. 권한 있는 다른 프로젝트에서 선택·편집한 지식을 가져와 대상 프로젝트에서 다시 검토 | 선택한 프로젝트의 확정 지식·회고를 쟁점 식별자로 비교. 리스크 규칙 자동 점검 및 Nora 상세 분석 지원. 통계적 모델 학습은 하지 않음 |

## 사용 순서

1. 좌측 **Main Context**를 연다. 기존 원문은 검색·프로젝트 기준에서 조회한다. 아직 발행하지 않은 자료는 `미확정 원문·검토 후보 포함`을 선택한다.
2. **회의·작업 맥락 기록**에서 회의록이나 작업 결과뿐 아니라 판단 근거, 대안, 미해결 질문, 발생·결정 시각, 채널을 기록하고 근거를 연결한다.
3. **Nora 분석**에서 1~20개 원문을 선택한다. 선택 당시의 원문 내용·해시·Main Context 버전을 고정해 실행한다.
4. Nora가 인용 근거와 분류 결과를 반환하면 AINS에서 검토 의견을 남기고 확인한다. 이 동작이 Nora 내부의 승인 대기 노드를 재개한다.
5. 완료된 분석 중 필요한 항목을 먼저 모두 **검토 후보 등록**한다. AI 후보의 발생 시각은 인용 자료의 시각을 제안값으로 사용하므로, 실제 결정 시각과 다르면 수정한다. 검토함에서 내용·질문·충돌을 수정하고 **프로젝트 기준에 반영**한다. 내부 검토 완료와 고객 합의는 별도 속성이다.
6. 기준이 바뀐 동안 작성한 후보는 **수정안 작성**으로 최신 기준에 맞춘다. 기존 후보를 덮어쓰지 않고 교체 이력을 남긴다.
7. **Daily Timeline**으로 선택한 날짜 09:00까지의 변화를 확인한다. 날짜만 있는 자료를 정확한 회의 시각으로 간주하지 않는다.
8. **지식 보관함**에서 해결 방식과 조건을 정리한다. 다른 프로젝트의 지식을 가져올 때는 원본 프로젝트 검토 권한과 대상 프로젝트 작성 권한이 모두 필요하다. 선택해 공유한 내용만 대상 검토 후보에 포함된다.

## 데이터 경계

- 기존 원문 테이블은 유지한다. `context-sources.js`가 프로젝트 권한 안에서 조회용 목록을 구성한다.
- `context_heads`: 프로젝트 기준 버전.
- `context_candidates`: 고정된 제안, 기준 버전, 원문 해시, 작성자, 검토 상태와 의견, 수정안 관계.
- `context_records`: 사람이 반영한 변경 불가 기록. 요구사항·결정·질문·변경·회고·회의·지식·메모를 구분한다.
- `context_supersessions`: 이전 기준을 어떤 기록이 어떤 근거로 대체했는지 보존한다.
- `context_ai_runs`: 고정된 분석 입력, Nora 실행 상태, 검토한 출력·해시, 검토 의견, 완료 결과, 가져온 후보 ID. Nora 승인 capability는 서버에만 보관한다.
- 지식 가져오기는 원본 프로젝트/기록/버전의 출처를 보존한다. 원본 열람 권한을 자동 부여하거나 원본 전체를 대상 프로젝트에 복제하지 않는다.
- 충돌 및 원문 변경 검사는 사람의 판단을 보조한다. 문장 의미가 같은지 여부를 확정하는 완전한 판정기는 아니다.

## API

모든 아래 경로는 `/api/projects/:projectId` 아래에 있고 세션·프로젝트 권한·변경 요청 CSRF 검사를 적용한다.

| 경로 | 역할 |
|---|---|
| `GET /context` | 기준 버전, 확정 기록, 후보, 실제 제공 기능 |
| `GET /context/search`, `/context/sources` | 기본 확정 자료 검색 / 분석 근거 선택 |
| `GET /context/sources/:type/:id` | 권한이 있는 원문 텍스트·출처 |
| `GET /context/timeline` | 반개구간 `[start,end)`의 프로젝트 변화 |
| `POST /context/candidates` | 멱등 요청 ID로 새 제안 등록 |
| `POST /context/candidates/:id/revisions` | 기존 후보를 보존한 수정안 등록 |
| `POST /context/candidates/:id/decision` | 검토한 해시·기준 버전에 대한 반영/반려 |
| `POST /context/knowledge/import` | 권한과 원문 버전을 확인한 지식 가져오기 |
| `GET/POST /context/ai-runs` | Nora 분석 이력 / 분석 요청 |
| `POST /context/ai-runs/:id/decision` | AINS 검토자 권한으로 Nora 승인/반려 |
| `POST /context/ai-runs/:id/import` | 완료·검토된 AI 항목을 일반 검토 후보로 등록 |

## Nora 실행·오류 처리

새 AINS 플로우는 `ains-main-context-review-v1`이며 `nora/context/`에 계약과 실제 호출 검증 기록을 보관한다. 기존 7개 플로우는 변경하지 않는다.

- 에이전트 1은 주어진 프로젝트 자료에서 근거가 있는 후보만 작성한다. 에이전트 2 **앞**의 `requiresApproval`에서 실제 실행을 멈춘다. 승인 후에는 검토한 내용을 그대로 반환해야 한다.
- AINS는 프로젝트/요청/버전 일치, 정확한 원문 인용, 기존 기록을 가리키는 충돌 관계, 승인 전후 동일 내용을 별도로 검증한다. Nora 자체 JSON 검증만으로 통과 여부를 판단하지 않는다.
- 승인 웹훅은 새 플로우에만 설정한다. 수신 URL의 비밀값을 검증한 뒤 고정된 Nora API에서 실제 승인 요청을 재조회한다. 전달받은 `decideUrl`을 임의 호출하지 않는다.
- 비정상 후보는 원래 요청과 연결이 검증된 경우에만 시스템 반려한다. 원문이나 기준이 바뀌면 승인 또는 후보 등록을 차단한다. 최종 프로젝트 반영 시 다시 검증한다.
- DB에 실행 요청을 저장한 뒤 작업자가 호출한다. 타임아웃·프로세스 중단은 `uncertain`이며 자동 재실행하지 않는다. Nora 승인 대기의 재시작 복구와 REST 최종 결과 재조회는 확인되지 않았으므로 운영자가 Nora 실행 이력에서 결과를 확인해야 한다.
- 승인 조작은 AINS 화면에서 수행한다. Nora에서 직접 승인한 실행은 AINS 검토자 기록이 없으므로 자동 가져오기가 허용되지 않는다.
- 의미 검색과 전사는 프로젝트 AI 연결 설정을 확인한다. 미설정·중지·실패 시 실제 상태와 키워드 대체 사유를 표시한다.

## 추가 구현 및 실행 방법 (2026-10-12)

- **프로젝트 설정 → 의미 검색·회의 전사 연결**: 관리자만 OpenAI 키를 등록·교체·삭제한다. 키는 프로젝트와 결합한 AES-256-GCM 암호문으로 보관한다. Nora에 저장된 키를 자동 복사하지 않는다. 서버에는 `AINS_CREDENTIAL_ENCRYPTION_KEY`를 설정한다.
- **외부 채널 연결**: Gmail 라벨, Drive 폴더, Slack/Discord/Teams 채널, GitHub 저장소를 지정해 연결하고 대상 접근 확인 후 수집을 시작한다. 새 연결은 일시 정지 상태다. 수집 내용은 기존 검토함에 들어간다. 카카오톡은 내보내기 파일·지정 파일 watcher·인증 브리지를 사용하며 Railway가 개인 PC의 대화방을 직접 읽지는 않는다. [상세 커넥터 범위](INTEGRATIONS.md).
- **Main Context → 의미 검색**: 검토자가 처음 색인을 시작한다. 승인된 최신 자료만 임베딩하고, 검색할 때 프로젝트·업무 영역·원문 해시·승인 철회를 재검증한다. 제한과 장애 시 키워드로 대체하며 이유를 표시한다. [검색 설정과 한도](SEMANTIC_SEARCH.md).
- **회의 전사**: 녹음을 업로드하고 원본 재생·시간 구간·화자 구분 결과를 대조한다. 전사 원문과 편집된 회의 기록을 분리 보존하고, 검토 후보로 등록한 뒤 기존 검토함에서 확정한다. [전사 모델·용량·오류 처리](TRANSCRIPTION.md).
- **Main Context → 리스크·회고**: 5분마다 기한 초과·임박, 보류 작업, 미해결 질문·충돌, 고객 합의 전 변경 요청, 근거 변경, 오래된 검토 기준, 완료 작업의 회고 누락을 점검한다. 규칙과 근거가 있는 제안이며 확률 예측이 아니다. 필요하면 근거를 Nora 상세 분석으로 넘겨 기존 내부 승인 플로우에서 검토한다.
- **Daily Brief**: 최근 완료된 09:00 KST 구간의 자료를 원문 링크와 함께 자동 집계한다. 발생 시각이 불명확하면 저장 시각을 사용했다는 표시를 유지한다. 보고서 내용별 해시와 버전을 보존한다.
- **반복된 문제와 해결 경험**: 검토 권한이 있는 프로젝트를 명시적으로 선택한다. 같은 쟁점 식별자를 가진 확정 지식·회고를 비교하며, 미승인·철회된 근거는 제외한다. 단순 반복 사실을 인과관계나 동일한 해결책으로 단정하지 않는다.

커넥터·임베딩·전사의 프로토콜과 실패 처리는 제어된 API 응답 및 격리 DB로 검증한다. 실제 외부 계정 수집과 모델 호출에는 대상 범위 및 서비스 키 등록이 필요하다. 플랫폼 내 리스크 점검·Daily Brief에는 별도 AI 키가 필요하지 않다.
