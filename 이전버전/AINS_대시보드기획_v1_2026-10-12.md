## 1. 먼저 만들어야 하는 것 (선행 관계)

맞아요, **점수가 높다고 바로 만들 수 있는 게 아니에요.** 어떤 기능은 다른 기능이 있어야 돌아가요.

### 0단계: 기능보다 먼저 정해야 하는 "바닥"
| 무엇 | 왜 먼저? |
|---|---|
| **프로젝트 / 고객사 구조** | 모든 자료는 "어느 고객사의 어느 프로젝트"에 들어가야 해요. 이 틀이 없으면 자료를 모을 곳이 없어요. |
| **Data Isolation** (고객사별 데이터 분리) | 자료를 저장하는 방식 자체가 달라져요. 나중에 바꾸려면 처음부터 다시 만들어야 해요. |
| **Access Control** (권한) | 누가 어떤 프로젝트를 볼 수 있는지 정해야 해요. |
| **Compliance** (고객사 보안 규칙) | 고객사가 외부 AI 사용이나 자료 반출을 막으면, 어떤 자료를 모을 수 있는지가 달라져요. |

→ 그래서 아이데이션에서도 **"보안은 처음 설계부터 넣어야 한다"** 고 결론 낸 거예요.

### 기능끼리의 선행 관계
```
[0단계] 프로젝트 구조 + 보안 (Data Isolation, Access Control, Compliance)
   │
[1단계] Context Integration  ── 자료를 모아야 뭐든 할 수 있어요
   │
   ├─ [2단계] Context Traceability  ── 모은 자료에서 "결정"을 뽑아 기록
   └─ [2단계] Smart Retrieval       ── 모은 자료를 찾기
          │
[3단계] Pre-flight Check          ← 합의된 범위(Traceability) + 검색(Retrieval)이 있어야 "이 요청이 범위 안인지" 판단 가능
        Risk Detection             ← 결정 기록과 비교해야 충돌을 찾음
        Scope & Conflict Control   ← 합의된 범위 기록이 필요
        Progress Monitoring        ← 업무/일정 데이터(WBS, 스프린트)를 따로 연결해야 함
   │
[4단계] Task Automation, Auto Deliverables  ← 위 데이터가 쌓여야 자동으로 보고서나 문서를 만듦
   │
[5단계] Knowledge Reuse, Pattern Library    ← 프로젝트가 여러 개 쌓여야 의미가 있음
        Planning Intelligence               ← 모든 맥락이 있어야 AI가 기획을 잘 도움
```

### 그래서 왜 이 순서인지
- **Pre-flight Check**는 점수 1등인데 순서는 5등이에요. **"원래 약속한 범위"가 기록되어 있어야** 새 요청을 점검할 수 있기 때문이에요. 기록 추적이 먼저예요.
- **Smart Retrieval**은 점수는 낮지만, 다른 기능들이 자료를 찾을 때 **내부 부품으로 쓰여서** 앞에 와요.

## 2. 대시보드의 목적

> **"프로젝트에 무슨 일이 있었고, 지금 뭘 조심해야 하는지 한눈에 보기"**

### 누가 쓰나
- **PM / 기획자**: 고객과 정한 내용, 남은 일, 고객 답장 기다리는 것
- **개발자 / 작업자**: 내 작업의 배경, 왜 이렇게 정했는지
- **중간에 들어온 팀원**: 프로젝트를 빨리 따라잡기

### 해결하려는 문제 (아이데이션의 문제 10개 중)
| 대시보드로 해결할 문제 | 해당 기능 |
|---|---|
| 1. 고객 소통 내용이 사라지고 공유가 안 됨 | Context Integration, Traceability |
| 2. 파악할 자료가 너무 많음 | Smart Retrieval |
| 3. 업무 기록이 흩어져 있음 | Context Integration |
| 4. 위험을 늦게 발견함 | Risk Detection, Pre-flight Check |
| 5. 고객 답장 지연을 모르고 지나감 | Progress Monitoring |
| 8. 원래 범위인지 추가인지 헷갈림 | Traceability, Pre-flight Check |

## 3. 화면 구성

### 화면 ① 홈: 내 프로젝트 한눈에
```
┌──────────────────────────────────────────────────────────┐
│ AINS                                    🔍 무엇이든 검색  │
├──────────────────────────────────────────────────────────┤
│ ⚠️ 오늘 확인할 것                                         │
│  · [씨젠] 고객 답장 5일째 대기 중 — "로그인 정책 확인"     │
│  · [A사] 새 요청이 기존 결정과 충돌할 수 있어요            │
├──────────────────────────────────────────────────────────┤
│ 내 프로젝트                                               │
│ ┌────────────┐ ┌────────────┐ ┌────────────┐             │
│ │ 씨젠        │ │ A사         │ │ B사         │             │
│ │ 기획/설계   │ │ 구현        │ │ 검수        │             │
│ │ ⚠️ 2  💬 1  │ │ ⚠️ 1        │ │ ✅          │             │
│ └────────────┘ └────────────┘ └────────────┘             │
└──────────────────────────────────────────────────────────┘
```
- 경고와 답장 대기는 3단계 기능이에요. **처음엔 프로젝트 카드만** 있어도 돼요.

### 화면 ② 프로젝트 상세 (핵심 화면)
```
┌──────────────────────────────────────────────────────────┐
│ 씨젠 프로젝트       단계: 계약 ▸ 요구사항 ▸ [기획/설계] ▸ 구현 │
├────────────┬─────────────────────────────────────────────┤
│ 📌 개요     │ 고객이 계약한 이유 (핵심 니즈)                │
│ 🕒 결정 기록 │ 합의된 범위 / 범위 밖                         │
│ 📁 자료함   │ 담당자 · 소통 채널                           │
│ 💬 질문하기 │                                              │
│ 📊 진행 현황 │                                              │
└────────────┴─────────────────────────────────────────────┘
```
왼쪽 메뉴로 탭을 바꿔요.

| 탭 | 보여 주는 것 | 기능 | 단계 |
|---|---|---|---|
| 📌 **개요** | 고객 니즈, 합의된 범위, 담당자 | Traceability | 1차 |
| 🕒 **결정 기록** | "언제, 누가, 무엇을, 왜 정했나" 타임라인. 각 항목에 원본(회의록, 메일) 링크 | **Traceability** | 1차 |
| 📁 **자료함** | 회의록, 메일, 슬랙, 문서를 한곳에. 최신본 표시 | **Integration** | 1차 |
| 💬 **질문하기** | "로그인 정책 어떻게 정했었지?" → AI가 답하고 출처를 보여 줌 | **Smart Retrieval** | 1차 |
| 📊 **진행 현황** | 단계, 남은 일, 고객 답장 대기 목록 | Progress Monitoring | 2차 |

#### 결정 기록 탭 예시
```
🕒 결정 기록                                    [필터: 전체 ▾]
──────────────────────────────────────────────────────────
10/08  로그인은 SSO만 지원하기로 함                  ✅ 고객 확인
       누가: 고객 담당자, 우리 담당자
       왜:   보안팀 정책 (외부 계정 금지)
       출처: 📝 10/08 회의록   ✉️ 확인 메일
──────────────────────────────────────────────────────────
10/02  관리자 화면은 2차 범위로 미룸                 ⏳ 고객 답장 대기
       출처: 💬 슬랙 #씨젠
```

### 화면 ③ 새 요청 점검 (Pre-flight Check, 2차)
```
┌──────────────────────────────────────────────────────────┐
│ 새 요청 점검                                              │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ (고객 요청 붙여넣기) "관리자 화면에 엑셀 다운로드…"    │ │
│ └──────────────────────────────────────────────────────┘ │
│                                         [점검하기]        │
├──────────────────────────────────────────────────────────┤
│ 🟡 범위 밖일 가능성: 관리자 화면은 10/02에 2차로 미룸     │
│ 🔴 충돌: 10/08 "개인정보 다운로드 금지" 결정과 충돌        │
│ 💡 고객에게 보낼 확인 질문 초안 [복사]                     │
└──────────────────────────────────────────────────────────┘
```

## 4. 단계별 계획

| 단계 | 만들 것 | 대시보드에 보이는 것 |
|---|---|---|
| **0. 바닥** | 프로젝트/고객사 구조, 로그인과 권한, 고객사별 데이터 분리 | 로그인, 프로젝트 목록 |
| **1. 프리뷰 (MVP)** | Integration, Traceability, Smart Retrieval | 프로젝트 상세: 개요, 결정 기록, 자료함, 질문하기 |
| **2. 점검** | Pre-flight Check, Risk Detection, Scope & Conflict Control, Progress Monitoring | 홈의 "오늘 확인할 것", 새 요청 점검, 진행 현황 |
| **3. 자동화** | Task Automation, Auto Deliverables | 주간 보고, 완료 보고 자동 작성 버튼 |
| **4. 지식** | Knowledge Reuse, Pattern Library, Planning Intelligence | 지난 프로젝트 추천, AI 기획 대화 (데스크탑 앱) |

- 1~3단계는 **웹**으로 충분해요. 데스크탑 앱은 4단계의 Planning Intelligence 때 필요해요.

## 5. 팀이 정해야 할 것

1. **자료를 어디서부터 모을까?** 슬랙, 메일, 팀즈, 회의록, 구글 드라이브, 피그마, 데브옵스 중 1차로 연결할 것 2~3개 고르기
   - 추천: **회의록 + 메일 + 슬랙**. 고객 결정이 가장 많이 나오는 곳이에요.
2. **결정 기록은 누가 확정할까?** AI가 자동으로 뽑고 사람이 승인할지, 사람이 직접 적을지
   - 추천: **AI가 뽑고 사람이 확인**. 잘못 기록되면 책임 소재 판단에 문제가 생겨요.
3. **고객사 보안**: 외부 AI 사용을 막는 고객사(예: 암호화 문서)는 어떻게 처리할지
4. **프리뷰 대상 프로젝트**: 실제 프로젝트 하나(예: 씨젠)로 먼저 테스트할지
5. **웹 먼저 vs 앱 같이**: 지난 회의에서는 앱으로 결정했지만, 프리뷰는 웹으로 먼저 할지
